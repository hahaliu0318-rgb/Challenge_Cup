# GitHub上传步骤

1. 2026-09-03已通过本机Git凭据访问目标私有仓库；首次拉取时仓库为空。用户授权创建 `phase1-release`，并上传本目录中的源码和少量示例。仓库保持私有，不更改访问设置。
2. 后续更新先比较远程文件，保留已有提交历史，不使用强制推送。源码只从独立提交目录收集，不把研究工作区直接推送。
3. 核对 `docs/VALIDATION.md`、第三方和示例许可、大文件下载字段。可以发布明确标为候选的源码，但不能把缺少权重链接的版本称为完整复现提交。
4. 仅在该独立发布目录运行检查，并检查将要提交的差异：

```bash
python3 scripts/check_release.py
git status --short
git diff --cached --stat
git diff --cached
```

5. 完成手动审阅后再暂存本次确定的文件并提交。下载的模型、`external/`、本机YAML、日志和任务库都应被忽略；不要从研究工作区根目录暂存所有文件。
6. 正常推送 `phase1-release`，通过远程commit比对及文件清单检查确认上传结果。不要上传服务器凭据、联系电话等个人信息。适配器按最新选择上传百度网盘，GitHub只保留其下载和核验信息。
7. 在干净机器按README试跑，再固定本次作品对应的commit/tag并同步填写模型下载清单中的版本。

GitHub源码链接不替代比赛要求的邮件压缩包和模型下载链接。
